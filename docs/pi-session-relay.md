# Pi 会话接力

接力将一个正在运行的 Pi TUI 会话绑定到一个飞书话题。飞书输入由该终端进程执行；TUI 显示用户消息、模型回复和工具执行，飞书只显示每轮结束时的正式回复。多个终端会话分别绑定不同话题，不共享“当前会话”指针。

## 前提

- 使用 Pi TUI 和持久会话；print、JSON、RPC 模式及内存会话不支持绑定。
- 使用已配置机器人且机器人可以发言的话题群。授权账号必须是群主的 `open_id`，不能填 `user_id` 或 `union_id`。
- 机器人需要已有的群信息读取和消息发送权限。无需 @ 的话题输入仍需要飞书后台授权机器人接收群内所有消息；扩展无法绕过飞书平台权限。
- 飞书网关和终端在同一台机器、同一操作系统账号下。接力不提供跨机器网络入口。
- 飞书用户拥有与本机 Pi 相同的工具能力；本机工具确认机制继续生效，需交互确认的操作可能仍需回终端处理。

## 安装与配置

此分支可通过 Git 安装，不要与旧的 `pi-feishu-lark` 或另一份 `ax-feishu-bridge` 同时加载：

```bash
pi install git:github.com/yuhaoxin/ax-feishu-bridge@feat/feishu-session-handoff
```

替换已有安装前先停止旧网关并备份配置。Pi 适配器使用 `~/.pi/agent/feishu/config.pi.json`、`state.pi.json`、`bridge.pi.json`；旧版的 `config.json`、`state.json`、`bridge.json` 不会自动迁移。可重新运行 `/feishu setup`；需要保留原映射时，在网关停止后备份并迁移对应文件，不覆盖已存在的新配置。恢复旧历史不等于建立接力绑定。

在终端中执行：

```text
/feishu start
/feishu relay setup oc_目标话题群 ou_你的账号
```

`setup` 读取群信息验证话题群及群主，不发送消息，并开启「新会话自动绑定」（默认开，可用 `/feishu relay autobind on|off` 切换）。此后每个新开的 Pi TUI 会话在发出第一条用户消息时自动创建一个独立话题；标题取「Pi 会话名 ‖ 首条用户消息前 30 字 ‖ 工作目录 basename」加会话短 ID。之后在 Pi 里修改会话名（`session_info_changed`）会自动更新话题标题；名字清空则保持不变。没有实际使用的会话不会创建话题。

接力配置只可通过终端命令设置，模型工具不能改变群或授权账号。已有话题后不允许更换目标群或账号，避免旧话题和权限发生歧义。

## 日常操作

```text
/feishu relay status
/feishu relay push 指定通知内容
/feishu relay unbind
```

模型可调用 `feishu_relay` 工具的 `status`、`push`、`unbind`、`autobind` 操作。显式推送应由用户明确要求。工具没有任意收件人参数，仅操作当前会话，也不能改变群或授权账号。

- 在绑定话题回复文本即可继续操作对应终端，无需在多个会话间执行 `/resume`。
- TUI 忙时使用 Pi 的 `steer` 队列，在工具执行边界引导当前任务，不强制中止运行中的工具。
- TUI 关闭、切换会话或接力断联时不交给后台接管；离线输入不排队、不自动重放。
- 同一会话重新打开后自动恢复连接和绑定。断线期间的输出不自动补发，需要时显式推送。
- 同一会话不能由两个 TUI 接力连接同时占用。已由普通飞书后台加载的会话不能接力注册；先在飞书切换到新会话并重启网关。
- 接力管理的会话不能再从普通飞书 `/resume` 路径驱动后台模型，避免两处写入同一历史。
- `unbind` = 本会话永久退出接力：解绑并记入退出名单，此后 `session_start` 不再自动绑定；旧话题继续拒绝执行。退出后想恢复只能删除会话重新打开（新会话 ID 会自动绑定）。`autobind off` 是全局开关，关闭后新会话都不建话题，已绑定的会话不受影响。
- 接力话题目前只接收文本（含纯文本富文本消息），不下载图片、文件或展开引用附件。斜杠命令作为普通输入送入 Pi，不执行飞书的 `/resume` 等后台管理命令。
- 普通、未绑定的飞书会话保持原有后台聊天行为；本功能的单账号限制只保护接力话题，不改变其他会话的访问策略。

## 正式回复

自动同步仅在 `agent_end` 发生时发送最后一条正常完成且不含工具调用的助手消息。思考块、工具参数、工具结果、失败或取消的草稿、流式中间内容均不发送。支持阶段标记的模型只保留 `final_answer`，过滤 `commentary`；没有阶段标记时以最后一条正常完成的文本答案为准。

飞书不显示生成中的流式卡片。正式答案分块发送到同一话题，保留完整内容（单轮最多 200000 字符，超限会在终端提示，不静默截断）。主动推送的单次文本最多 100000 字符。离线、忙时送达及投递不确定等必要状态提示不属于模型输出，仍会显示。

不支持 cron 或关闭终端后执行任务。这里的任务结果推送就是活跃 TUI 完成一轮后的正式回复同步。

## 安全与故障

网关只监听 `127.0.0.1` 随机端口，以每次启动重新生成的随机令牌校验本机连接。令牌文件为当前用户可读写的 `0600` 文件；同一操作系统账号下的进程属于同一信任边界，不防御该账号内的恶意进程。

| 文件 | 内容 |
| --- | --- |
| `~/.pi/agent/feishu/relay-state.pi.json` | 机器人 ID、授权账号、绑定（含解绑记录）、投递记录 |
| `~/.pi/agent/feishu/relay-endpoint.pi.json` | 网关本机端口和随机令牌，不应分享或提交 |

入站消息先记录再注入，故障后不会重试可能已执行过的指令。投递确认仅表示终端调用了消息注入接口，不表示模型或工具已完成。断联、超时或失败时可能已接收或部分发送，需要检查终端/飞书后再决定是否重发；不宣称“恰好执行一次”。

话题创建前持久化 `pendingTopic`。若创建接口超时或创建后的状态落盘失败，无法确定是否留下孤立话题，网关会暂停新建及目标群的普通后台分派，已有绑定话题仍按原路由处理。恢复步骤：停止网关，备份接力状态；在飞书确认并删除或明确弃用孤立话题后，移除状态中的 `pendingTopic` 再启动。不要仅清空整个状态文件，否则旧接力话题可能回落到普通后台会话。

`/feishu reset` 保留接力状态。更换机器人前需要单独规划旧话题清理和状态迁移；机器人 ID 不匹配时网关拒绝启动接力，不能使用其他机器人的绑定。

```bash
npm ci

npm test
```

上游测试脚本使用 `--experimental-transform-types`，请用 Node 24 运行；Node 26 已删除该参数。测试覆盖真实环回 TCP、多会话隔离、账号校验、去重、离线和解绑拒绝、重连、正式回复过滤，以及真实 Pi SDK 配合本地模型 HTTP 替身的端到端处理。测试不使用生产机器人凭证，也不向飞书外发。
